## Endpoints da API

### Veículos (`/api/vehicles`)
- `GET /` - Listar veículos ativos
- `GET /inactive` - Listar veículos inativos
- `GET /:id` - Buscar veículo por ID
- `POST /` - Criar veículo
- `PUT /:id` - Atualizar veículo
- `PUT /:id/inactivate` - Inativar veículo
- `PUT /:id/reactivate` - Reativar veículo
- `DELETE /:id` - Deletar permanentemente

### Manutenções (`/api/maintenances`)
- `GET /` - Listar manutenções
- `GET /:id` - Buscar manutenção por ID
- `POST /` - Criar manutenção
- `PUT /:id` - Atualizar manutenção
- `PUT /:id/complete` - Marcar como concluída
- `DELETE /:id` - Deletar manutenção

### Anexos de Manutenção (`/api/maintenance-attachments`)
- `GET /:maintenanceId` - Listar anexos
- `POST /:maintenanceId` - Upload de anexos
- `GET /:maintenanceId/:id/download` - Download de anexo
- `PUT /:maintenanceId/:id` - Atualizar nome do anexo
- `DELETE /:maintenanceId/:id` - Deletar anexo

## Problemas Conhecidos e Soluções

### 1. Service Worker Caching
- **Problema:** Service Worker cacheia versões antigas do app
- **Solução:** Desabilitado durante desenvolvimento em `+layout.svelte`
- **Nota:** Reativar para produção

### 2. Hot Reload e Edição de Arquivos
- **Problema:** Vite hot reload causa conflitos ao usar Edit tool
- **Solução:** Usar bash commands (sed) quando Edit falha

### 3. URL da API
- **Problema:** API URL sem protocolo causa requisições erradas
- **Solução:** Sempre incluir `https://` no .env
- **Nota:** Reiniciar dev server após mudar .env

### 4. Autenticação
- **Implementação:** Server-first usando cookies
- **Store:** `authStore` para estado reativo no cliente
- **Proteção:** `ProtectedRoute` component e `+layout.server.ts`
